# 学习发送与知乎调用验收

日期：2026-09-08。范围：本地 PGlite、真实模型与知乎 provider、Codex 浏览器；不代表生产部署或负载验收。代码基线为 `a880995` 后本轮工作区修改。

## 原始故障与修正

| 问题 | 现场证据 | 修正 |
| --- | --- | --- |
| 作者说明与操作文字挤在一起 | 文章详情把身份说明和操作放在同一行 | 身份说明与独立描边按钮分行；保留真实作者入口 |
| 问博主像没有响应 | 发送请求实际被接收；两路搜索成功，各 10 条候选；A-card-select 连续三次被同一个笼统的证据/作者校验拒绝，任务进入等待；画布缺少显眼的恢复入口 | 本次短编号选择并由服务器回查原始证据；错误明确到越界项或重复身份；发送中即时反馈、防重复点击、失败保留草稿；画布显示继续/停止 |
| 首次概念讲解重试很久 | 两个直答在约 4.06/5.28 秒失败，一个约 33.98 秒成功；恢复后其余两个成功，整个任务约 91.94 秒 | 补齐空响应、解析、未完成、网络/超时错误的安全诊断；HTTP 200 携带限流业务码也触发共享冷却，遵守 Retry-After |

旧失败没有记录可区分的错误码和响应诊断，不能追溯断言它们就是 HTTP 429 或并发限制。A-card-select 的旧诊断同样不能区分抄错证据编号与重复作者；本次反馈分别处理这两种原因，不把猜测写成已证实根因。

## 真实调用

首次概念使用相同上下文重测三个 L0a 角度。通过正式共享额度调度，未写入学习结果：

| 项目 | 结果 |
| --- | --- |
| 请求开始时间（UTC） | 09:48:14.212、09:48:16.319、09:48:41.790 |
| 第一、第二次启动间距 | 2107 ms |
| 并发 | 最多两路；第三路等名额释放 |
| 响应 | 三次均 HTTP 200、JSON 正文完整、finish_reason=stop |
| 上游耗时 | 约 24.41、27.12、28.33 秒 |

保留现有 2100 ms 最小启动间隔与两路并发；本样本未发生限流，不能据此声称全局最优间隔或保证永不限流。业务限流共享冷却另由隔离测试覆盖。

用户明确同意继续原来的“详细讲解一下”请求后，通过页面“继续完成”恢复 `814bf888-b7eb-4536-a846-ba50b2bda8c4`：服务器记录 `task.completed`，本次恢复耗时 2376 ms（复用此前已经完成的检查点，不是完整新搜索耗时）。

独立后台标签重新打开真实学习资源后核对：

- 对话内“详细讲解一下”只有一条。
- 三张作者观点卡已保存，ID 为上述任务 ID 对应的 `author-…-0/1/2`。
- 三张卡的唯一父节点均为用户所选的“为什么评测体系是必要的：验证边界是否被正确补上”。
- 无 pending 卡、无等待恢复提示；原文链接可见，内容仍按公开文章观点展示。
- 两张原文显示昵称 llmbases，另一张显示 AIGC导师。搜索接口缺少跨文章稳定作者身份，因此本次证据只证明保存了三张原文观点卡，不能证明三位不同自然人；没有按昵称合并身份。跨文章身份完备性仍是 [产品中记录的缺口](../../../docs/product.md#42-仍需实际验收或外部配置)。
