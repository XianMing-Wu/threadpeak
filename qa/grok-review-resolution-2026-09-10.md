# 两份 Grok 审查的逐项复核与修复

复核日期：2026-09-10 UTC（本机太平洋时间 2026-09-09）。起始分支 `main`，基线 `d602806`。审查输入为仓库根目录的 `grok后端审查报告.md` 与 `grok前端审查报告.md`；报告中的建议不是产品裁决，也不构成运行脚本、删除数据或部署的授权。

范围包含前端 F-01–F-46、后端 21 个分级条目、12 个优化条目，以及两份报告附带的安全、合同张力、测试和上线判断。重复出现的建议归入同一编号。判定依据为[产品说明](../docs/product.md)、[完整 Agent 合同](../docs/agents.md)、匹配规则、源码调用链和本次验证。不是照报告批量修改。

| P2-2 | 需要修正，保留现状 | 合同 0.1 把正常结束的非空正式正文与不完整传输分开；`finish_reason=length` 不能视为一份完整模型答复。现有行为是任务级有界恢复，不是把半截结果发布，也不是无限重试。把 length 转成结构修复是另一种恢复策略，没有证据证明同样窗口/同样输出预算的修复更有效；还可能和任务重试叠加成本。本次不扩大调用预算、不让半截正文进入成功校验。 |

| P2-5 | 准确，已修复 | 生成、问答、作者检索/导入、来源展示和恢复入口在 provider 未配置时直接 503；首次聊天/学习不创建一个注定失败的任务，已有记录仍可读取。ready 只证明配置满足启动条件，不能把远端未来故障预测成可用。 |

| P2-8 | 准确，已修复活动路由 | `planStep('R3')` 进入当前 `routeInterview`，活动规格引用 2–4 题、3 选项的实际提示词。删除未使用的修复常量和旧 `createZhihuSearchAdapter`（静默截短查询的入口）。共享 URL/响应解析仍被真实 provider 使用，旧 schema 只作历史兼容和独立测试，未把整个旧模块误删。 |
| P2-9 | 部分准确，已修复大读取 | [ownedPath](../server/durable/learning-goal.ts) 按账号和资源/文档/路线 ID 定位，不再把所有路线正文拉回再 find。[作者网络](../server/durable/authors-network.ts) 的 path、attachment 原本已经是字段投影，报告说全都 SELECT * 不准确；本次将 learning 也投影化，去掉不需的教学正文，保留原始作者段落及用户问题关系。首次成功网络检查点保持冻结，这是同一任务恢复的输入稳定性，不在重试中悄悄换一套反馈。新任务会读取新反馈。 |
| P2-10 | 部分准确，已修复可安全释放部分 | `tp_memories` 不清理与工程文档“来源摘要没有新增过期政策”一致；报告没有授权制定资料删除期限。[PDF 管线](../server/durable/materials.ts) 在远端上传 ID 已成为持久检查点后立即删除对应 base64，之后解析失败仍能从检查点恢复。上传成功前的 waiting/cancelled 若只有该副本，仍保留；按状态全删会直接破坏产品恢复合同。 |
| P2-11 | 部分准确，不擅自缩小业务上限 | 20 MB/2 万节点、3D 1M 字符确实是当前上限；树校验和布局已经迭代化，且允许大型学习树、不透明 renderer blob。报告没有测量可承受阈值，不能凭数字大就任意裁短用户已有树或解析 renderer 数据。本次补资料持久额度和上传内存并发；学习编辑仍受已认证 owner/IP 请求限流、body 上限和完整树校验。整库容量及峰值 RSS 仍需负载测试。 |
| P2-12 | 准确，已修复 | [worker](../server/durable/worker.ts) 在 handler 返回后读取原 job 的 status/fence，仍 running 即显式失败等待；日志按实际终态命名。直接 execute 的测试不启动额外 pump。 |
| P2-13 | 部分准确，已修复重复领取 | claim 排除本 worker controllers 中的 ID，避免覆盖控制器。本地 PGlite 的单进程目录不能另开第二个写者；不能照搬“独立连接”到本地模式。生产 postgres.js 本就有连接池，隔离维护且语句有界；心跳拥塞的实际压力门槛仍需生产测量。 |
| P2-14 | 准确描述上线边界，不改会话产品 | 当前退出只撤销当前活动 cookie；游客恢复、OAuth 会话和网关 JWT 生命周期各有合同。全设备下线、凭据失窃响应、JWT jti 黑名单是额外身份功能，报告也明确“不一定违反当前裁决”。本次不把“退出本设备”改成清理全部设备身份。 |
| P2-15 | 准确，已修复回查基础 | R2 使用未压缩的本次 goal/firstSearch/附件做名称回查，摘要中自行出现的书名不能获得来源资格；摘要策略要求完整保留书课名称和版本，并同步文档。仍可能有模型漏提名称，规则不能保证长上下文召回质量；未把此修复宣称为真实模型语义验收。 |

## 后端优化条目

| 编号 | 建议 | 判定与处理 |
| --- | --- | --- |
| O-01 | 完成后 wake | 认可并修复：运行中的 worker 释放槽位后立即唤醒；直接 execute 不意外开启常驻循环。 |
| O-02 | claim / existingCommand 只读哈希 | 需要修正：执行必须读取冻结 input/checkpoints；HTTP 去重也比较资源、kind、原 intent，历史压缩回执另有哈希兼容。并非“只需 input_hash”，不删除恢复数据。快照读取已独立投影。 |
| O-03 | withPermit 删除初始化 INSERT | 不直接采纳：槽位包含可配置池和动态缓存池，INSERT ON CONFLICT 保证跨进程初始化/重建；仅改成进程内初始化可能与维护/多进程有竞态。无量化瓶颈证据。 |
| O-04 | 每步指标 INSERT | 现象准确，保留：checkpoint hit 与真实调用不同，正需要指标区分；已有 7 天有界清理。直接不记会丢恢复/缓存观测。批量落库需单独测量与可接受丢失窗口。 |
| O-05 | 连接池固定 10 | 参数现状准确，“容易排队成 503”未证实。4 并发 provider 不等于长期占用 4 个 SQL 连接，HTTP 队列也有独立限流；本次不未经连接预算就扩大连接池。生产副本数与数据库最大连接数需一起确定。 |
| O-06 | 维护 5s 超时整批回滚 | 准确但已有保护：批大小、锁超时、独立维护、失败退避均在。把批次随意拆开不是当前业务错误的必要修复；超大存量要以 EXPLAIN/维护日志确定批次大小。 |
| O-07 | routePlan 两次编译 | 现象准确，保留：第一次在保存结构化检查点前拒绝非法计划；之后从返回/恢复的计划重建 route。第二次为本地确定性计算，不是两次模型调用。消除须改变 checkpoint 输出契约，未证明收益值得迁移。 |
| O-08 | firstLessonFocus 重复目标 | 不认可盲删：长证据后重申原话是 Agent 合同要求，并已预留预算、纳入缓存身份；它不是意外复制。真实教学范围偏移尚未闭合时不能为少量 tokens 删除需求提醒。 |
| O-09 | 收藏范围 R1 成本 | 与 P2-7 重复，已让问法实际用于资料整理。R1 不是可凭成本擅自删除的步骤。 |
| O-10 | drizzle-orm 未使用 | 认可，已从 manifest 和 lockfile 移除，运行时保持现有参数化 SQL。 |
| O-11 | ops 脏数值 cast | 认可并修复：[指标读取](../server/durable/ops-metrics.ts) 对数值类型、长度/整数范围做条件转换，无效值记为缺测，不能拖垮整个诊断报告。 |
| O-12 | 多副本时钟偏差 | 风险成立，不能写成已发生故障。租约仍以应用时钟、HTTP 窗口以数据库时钟计时；部署必须保持副本时钟同步。没有模拟偏差/真实多副本证据，本轮不声称已解决时钟漂移，也不为改时钟重写整个任务与 permit 协议。该项保留为部署验收风险。 |

## 附加安全、性能和合同判断

- 后端第 2 节的既有边界基本成立：固定工作流、所有者、fence、同事务发布、正式正文检查、知乎两路与冷却均保留。其“旧 R4 补造成功已删除”与本轮基线相符；没有重新引入 salvage、reasoning 兜底、judge 或假成功。
- 后端第 6 节三项：仅收藏范围显式问博主仍按产品 4.1 站内搜；文章节点允许编辑的是副本，articles 原来源保留；合法网关 Bearer 可调用业务 API。这三项不应作为漏洞修复。
- 后端第 7 节称 `0.0.0.0/0` 会通过配置校验，事实错误：原函数已经要求 prefix >= 1，IPv4/IPv6 的 `/0` 均拒绝，本轮增加行为断言。
- 无独立 CSRF token 的事实成立；不能仅凭其缺失判定当前 SameSite/Origin/Fetch Metadata 组合已被绕过，也不能把组合当成全场景安全证明。[OWASP 指南](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) 对来源缺失的回退策略和不同请求类型有专门讨论，网关/浏览器需区分。OAuth userinfo、全设备撤销、删除期限仍待真实身份/产品裁决。
- HTTP parser 的隔离依据 [Fastify 钩子与作用域](https://fastify.dev/docs/latest/Reference/Hooks/)；本次同时以实际路由测试确认原始上传格式不会进入聊天路由。
- 前端性能第 6 节的 1–3、来源轮询分别见 F-26、F-29、F-38、F-18。元数据串行队列与服务端两路限额同时存在，不盲目提高头像并发；卸载现可取消读者。
- 路线 onStopRef/onSender 每 render 绑定是廉价赋值并保持最新闭包，不是注册多个 DOM 监听器；只加空依赖会捕获过期题组。KaTeX CSS 为共享 Markdown/示例使用，拆路由 CSS 的收益需要下载/缓存测量。OrbitField 已尊重隐藏/减少动效，3D 与书架也没有同时挂载，未扩大重构。
- 两份报告列出的真实 OAuth、provider 语义、扫描 PDF、PostgreSQL 多进程/负载、跨设备 3D 冲突、备份恢复与安全渗透均不能由离线成功替代。产品 4.2 继续保留。
