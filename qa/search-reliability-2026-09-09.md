# 搜索规划误拦截修复 · 2026-09-09

范围：本地工作区、截图对应的真实 Transformer 任务，以及独立测试会话的真实 HTTP 路线流程。未部署生产，不将结构通过等同于全部教学语义正确。

## 现场原因

用户输入为“我想要快速理解transformer，请给我规划一下”。准备任务在 12.335 秒后停为 waiting / STRUCTURE_NOT_SETTLED。三次 DeepSeek 请求均 HTTP 200、正式正文完成；其 JSON 均已通过 R1 schema。失败发生在随后附加的关键词正则，依次误拦截：

1. transformer先看论文还是先看讲解
2. transformer先看代码还是先看讲解
3. transformer先看论文还是先看教程

这些问法表达学习顺序和载体取舍，符合用户目标。旧程序却要求每条命中固定“学习/推荐/选择”等词，将合理表达当作结构错误，迫使模型重复改写，三次后交给用户手动重试。现场上下文未发生压缩，不能归因于窗口不足。

另外，R1 附带的 JSON 示例只有两条且重复使用同一个 ID，与四至五条、ID 唯一的 schema 冲突。这不是现场三次的直接失败原因，但会诱导其他输入发生额外修复。

## 修改

- 删除 R1 学习意图的关键词硬拦截；语义要求仍完整保留于当前 Agent 提示词。数量、长度、枚举、唯一性及两路打包校验继续执行。
- 删除 R3 中用关键词判断时间题、用载体名出现与否判断预选课程的同类拦截。例如“若已掌握则不重复 GAMES101 基础复习”不能因为出现 GAMES101 就被判定为强制学课。访谈的内容原则和结构校验保留。
- R1 示例改为四条唯一 ID、两种 angle 的合法对象，新增测试要求示例通过真实 schema 与打包函数。
- 保留同 Agent、同提示词、同深度的格式修复，现有临时故障退避、检查点复用和取消栅栏。未增加独立 judge、虚构默认路线或无限重试。

## 实测

| 样本 | 结果 | 时间 |
| --- | --- | --- |
| 原失败任务恢复 | 同一任务、同一资源保留；R1 一次通过；两路真实搜索；R2 未发现需要目录补查的载体；两道题等待用户回答，无代填 | 19.243 秒 |
| 独立 HTTP 测试会话 | 同一目标；用明确标记的测试条件回答访谈；R4 发布 4 个载体、10 个概念，程序投影与路线校验通过 | 60.788 秒 |

原任务恢复中的模型用时：R1 4.523 秒、R2 1.978 秒、R3 9.664 秒；两路搜索的整体完成等待约 3 秒。调用使用同一数据库的共享知乎两路额度与 2.1 秒启动间隔。两次真实准备过程均无结构修复。独立会话最终规划任务用时 38.395 秒，无任务级重试。

检查点、诊断、原始查询与实测快照保留在 Git 忽略的 `.local-backend-review/11-task-recovery/`。HTTP 测试 Cookie 仅在测试进程内存中使用，不写入证据文件。

## 回归

新增五项行为回归：三个真实误判及自然表达变体一次通过；JSON 示例符合合同；坏 JSON 和错误字段由同一 Agent 修复；503 后恢复同一任务且复用已成功步骤；访谈中的经历询问与条件性课程提及不被字符串匹配拦截。

- `npm test`：422 项 Node 测试、55 项 UI 测试通过。
- `npm run check`、`npm run lint`、`npm run build`、`npm run check:docs` 通过。
- 第一次全测中的本地监听测试受沙箱 EPERM 阻止；允许临时端口监听后完整重跑通过。
- 构建仍有既有大分包提示，与本次修复无关。

## 边界

本次证明误判根因被移除、正式格式约束仍有效以及两个真实任务能继续。没有在本次重新审校所有教学内容；独立路线仍可优化已会矩阵操作的复习粒度。持续服务中断、配置失效及三次仍无合法正式输出的任务仍会保留进度并等待处理，不能宣称只有用户断网才可能遇到失败。此次没有修改用户原任务的访谈答案或已发布内容。
