- 原始请求和搜索响应仅保存在本机 `raw/`，由 Git 忽略；不随源码发布第三方完整响应或服务端调用上下文。
- 自动回归 524 项通过，类型检查及生产构建通过。构建仍报告既有的大包体积提示。数量包含历史模块，不能换算成模型的准确率。
- 浏览器在独立 localhost 测试服务实际操作：三项建议加自定义输入；空白不能提交；自定义回答保存后显示只读状态；一次只出现下一个待答问题；全部答完自动发布路线。此项使用显式测试 provider，验证交互，不代表模型表现。
- HTTP 集成覆盖重新读取保存答案、重复请求不重复生成、旧学习资源直接打开的目标回填、拒绝跨所有者回填、新对话继续保留路线目标。

## 样本驱动的修正

1. R2 混填检索证据 ID 与 F 附件编号：分开字段和来源校验，给同 Agent 可执行的修复原因。
2. 摘要把作者条件建议变成“本用户应该学”：摘要只能保留源信息，不能代替用户作目标决策；缓存区分用途。
3. R4 虚构收入、偏好、技能：基础、动机、限制、非目标必须逐字回查用户原话；个人未知保持未知，不能通过 assumptions 绕过。
4. 上传 PDF 的泛化总结漏掉数学：规划优先读取已有完整解析正文，随后才按真实目标压缩，原文不改写。
5. 首次讲解逐篇改写，膨胀成很多卡片：全部材料仍审阅，正文按当前概念组织，同一要点不重复；首次最多 8 段、追问最多 12 段，超限同 Agent 修复。
6. 技术来源混用版本和数学结论漏条件：强化同一实现方案、明确版本及推导条件。版本核对参考 [Three.js 官方安装文档](https://threejs.org/manual/en/installation.html)，其模块与 addons 应使用同一明确版本。

## 质量边界

这些样本证明调用、保存、合同及部分目标对齐行为，不能证明全部教学事实正确。逐字引文校验只证明文字存在，不证明来源结论或推导成立；语义正确性仍需要持续审阅；当前快答样本尚有技术引入方案并列/版本混用、数学前提省略和例子自洽性问题，不能将最终讲解标为全面达标。样本中仍可看到预算练习的组织重复、某些 openQuestions 重问已知信息等表达质量问题，应保留作为后续回归案例，而不能只统计“生成成功”。长文摘要质量、复杂扫描 PDF、任意长度不可压缩骨架及生产负载不在本次通过声明内。

## 复现

在配置真实 provider 后运行（会实际调用服务）：

```sh
node scripts/evaluate-goal-agents.mjs paper-math collection finance minimal-3d llm-job --route-only
node scripts/evaluate-goal-agents.mjs paper-math minimal-3d --learning-only
node scripts/evaluate-goal-answer.mjs paper-math minimal-3d
node scripts/summarize-goal-evaluation.mjs
```

第三条复用第二条保存的真实检索与三路直答，只重新检查最终讲解，不冒称重新执行整条检索链。
