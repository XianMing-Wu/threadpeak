# 知乎限流与模型缓存修正

## 现场证据

2026-09-07，使用当前生产适配器和共享数据库门控做受控请求：直答日额度尚余 68 次，相隔 4ms 的两次调用分别返回 200 和 429；失败原码为 `rate_limit_exceeded`，没有 Retry-After。相隔 2100ms 的第二组调用执行时间重叠，两次均 200，日额度由 67 降至 65。证据支持短时间集中发送触发频率限制，不支持日额度耗尽或必定只能串行的解释。平台没有公开数值阈值；2.1 秒是本次验证后的保守调度值，无法约束其他应用对同一凭据的调用或保证上游永不报错。

当前等待任务另有独立问题：递归分块讲解中的程序分隔符 `\n\n` 被自动公式识别当作 LaTeX，连续三次校验失败。须保护这些字面程序转义，不能将它们改为真正换行或跳过全部公式校验。

## 实施合同

- 全知乎共用两路在途名额及 2100ms 发送间隔，持久冷却遵守 Retry-After；发送间隔不占用工作线程，不丢问法。
- 频率、额度、鉴权与结构失败分别标记，诊断保存 provider、模型、任务/步骤、状态、白名单错误码及实际用量，不保存原始请求/错误正文或密钥。
- DeepSeek 自动 KV 缓存：账号哈希 user_id、稳定 JSON 顺序（材料在前，对话/当前问题在后），流式和非流式真实 usage。无 usage 的字段保持未知，不虚构命中率。最终回复每次重新生成。
- 知乎应用直答缓存：24 小时、完整成功 stop、精确完整请求/账号/版本/凭据命名空间；共享租约合并同键并发，失败和取消不缓存。缓存 TTL 与模型/提示合同变更共同控制失效；检索保持 network-first。
- 官方直答模型区分快速与深度，不使用未公开的 thinking/cache_control 参数。

## 依据

- [知乎额度查询](https://developer.zhihu.com/docs?key=quota)：日计数与请求频率为不同限制；公共文档由同域 `/console/api/v3/docs` 返回。
- [知乎直答](https://developer.zhihu.com/docs?key=zhida)：模型、消息和 stream 合同。
- [DeepSeek 上下文缓存](https://api-docs.deepseek.com/guides/kv_cache/)：默认启用、前缀命中及实际用量。
- [DeepSeek Chat Completion](https://api-docs.deepseek.com/api/create-chat-completion/)：user_id 隔离、stream_options 与 usage。

## 验证

- `npm test`：562 项通过，含同库启动间隔/两路占用、全部知乎适配器共享、429/业务频控、缓存同键合并/隔离/失效/重启、取消写入回滚、缺失用量/流式用量与公式识别回归；`npm run check`、`npm run build` 通过。构建仍报告既有大 bundle 提示，本轮未调整页面样式或动画。
- 快速直答：同时提交三项请求（其中两项完全相同），实际只发出两次 HTTP，间隔 2263ms，两次均 200；相同项结果缓存命中。
- 深度直答：实际请求 `zhida-thinking-1p5` 成功，约 2.5 秒；第二次同请求约 1ms 缓存命中，上游调用数仍为 1。随后关闭服务、重开数据库，对同一真实缓存重复请求仍命中，没有调用上游。
- DeepSeek 三次受控调用：首次 4349 输入 token 全未命中；第二次（流式）4224 命中、125 未命中；第三次改末尾问题，同样 4224 命中。该结果只证明重复前缀复用生效，不代表所有产品请求的命中率。恢复学习的两个首次新作用域调用实际命中为 0，也如实记录。
- 一条真实 RAG 学习任务因程序分隔符误判连续三次失败；修复后由原检查点恢复，同一任务约 18 秒完成正文及 8 张卡片。恢复仅新增两次 DeepSeek 调用，搜索和三角度直答均未重做。未恢复用户已明确停止的向量追问。
- 浏览器：当前知识脉络正常打开，另一个已完成向量学习仍完整显示；阅读实验页宽版和 320px 窄卡均把 `\n\n`、`\n`、`\t`、`\r\n` 显示为代码，`\nu` 正常显示为希腊字母，控制台无错误或警告。源原文保持不变，共享阅读政策升至 v5。

运行诊断保存 `tp_provider_calls`（7 天，按账号/任务/步骤定位），知乎直答结果保存在 `tp_provider_cache`（24 小时，过期清理）；命中日志不重复计入原调用的 token 用量。原始探测响应及任务快照只保存在本机临时目录，未加入仓库。
