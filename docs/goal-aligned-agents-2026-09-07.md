# 围绕真实目标的 Agent 重构

本轮用户裁决：路线解决的是“我为了什么而学、怎样达到这个目标”，不能输出与目标和资料脱节的通用课程目录。知乎建议的差异需要放回作者的用途、基础、约束和取舍中解释。访谈使用三个建议选项加用户自定义输入；选项帮助表达，自定义答案与选项答案具有同等效力。

## 目标与上下文

- 保留用户最初目标、每轮实际回答和自定义原话。画像字段逐字回查真实表达，未知个人情况单独保留为未知，不把作者意见当作用户意愿。
- R2 保留各建议适合谁、条件与代价、来源绑定、候选概念服务什么成果及材料关系。弃用只有“概念名＋争议布尔值”的有损探索格式。
- R3 以亲近的访谈确认真正会改变路线的未知条件，不重复询问已说清的信息，不考察陌生术语。每题三项建议，第四项由用户自由填写。自定义答案独立保存，不捏造 optionId 或 routeEffect。
- R3b 先回应用户的困惑。解释本身不必换题；只有当前题已不适用时才换成下一轮，最多三轮。保留所有真实问答，较新的明确表达优先。
- R4 根据原话、访谈、探索和全部材料整理最终目标。路线是相对于该目标的最小充分内容：读论文、复现、做作品、应试、求职和系统掌握的充分性标准不同。必要基础不能删掉，无关课程不能为了完整感加进来。
- 每个概念明确为何需要、学到什么程度、怎样判断够用。PDF 规划优先读取完整解析正文再按目标压缩，原始正文及独立总结仍保存。上传/导入资料存在时，每个概念须以真实材料片段说明直接关联或作为该片段所需的前置知识；不能把传入附件目录当作已经围绕材料设计。
- 最终目标和概念任务跟随路线进入首次检索、材料筛选、三角度直答、首次讲解、后续追问和找人请教。新对话清空旧聊天，仍保留路线目标；用户显式选卡限制证据范围，不抹去学习目的。

## 压缩


发送顺序为较长来源在前、不可压缩的真实目标与最新问题在后，不重复或删减数据来获得位置优势。摘要请求同样把本次用途放在原文块之后。

- 目标、用户回答、条件/否定、引用映射与结构是不可压缩骨架。压缩只作用于来源正文、旧普通对话和辅助讲解，不压缩成另一个用户目标。
- 分块以段落、公式与代码边界优先；保留来源路径、块顺序，超长块仍完整覆盖。摘要同时携带本次用途，保留数学关系、必要假设、不同观点及适用条件。
- 缓存绑定所有者、原文、用途、深度、预算与压缩合同版本；同一材料为了看懂推导和为了实现作品的摘要不能串用。
- 每份来源独立缩短，不把同作者的多篇材料合成一篇的证据。压缩失败不截字符串、不返回原文前缀。每次摘要调用也预留输出与安全预算；不足时明确失败并保留检查点。

## 不变的边界

服务端固定编排、同 Agent 修复、真实 provider、资料原文不可覆盖、持久任务及所有者隔离保持。路线阶段仍由程序编译稳定 ID 与 DAG；发布不创建知识树。学习段落仍是一张材料一个父卡。没有新增 judge，不将格式验证等同于语义质量。

## 本次验收

覆盖：论文数学、仅收藏夹系统学习、观点冲突、目标明确的最小 3D 作品路线、求职路线；同时验证自定义回答及刷新、最终目标跨学习入口/新对话保持、压缩用途隔离、来源片段回查及未知引用拒绝。524 项自动回归、类型检查与构建通过；五种情境都得到真实路线，论文与 3D 走通首次学习。浏览器完成三项建议、自定义答案、逐题推进和自动发布操作。完整证据与尚存语义问题见 [验收记录](../qa/goal-agents-2026-09-07/README.md)。

首次讲解将全部来源审阅与正文组织分开：正文按当前概念、用户目标去重；首次最多 8 段、追问最多 12 段，超限由同一 Agent 修复，不截结果发布。该数值是本次工程输出边界。技术来源不能混用版本，数学陈述不能丢必要前提；语法/引文校验无法替代事实核实。
