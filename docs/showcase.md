# 首页示例与内容维护

预备知识脉络与学习路线统一为系统理财、摄影、大模型三组。路线共 44 个概念；每条只按顺序预置前三个概念的首轮讲解，共 9 个学习状态、49 个讲解块、44 条按概念保存的来源记录。示例复用当前路线、来源阅读、连续讲解和知识树组件，与个人资源隔离。

## 目标、访谈与载体

| 目标 | 访谈后的起点与成果 | 载体与依赖 |
| --- | --- | --- |
| 系统学习理财 | 会四则运算和百分数，没有完整账本或投资经验；用虚拟家庭比较条款并写出决策依据 | 看清家庭的钱 → **保障与家庭责任 / 投资、风险与长期目标** → 比较条款，形成自己的判断 |
| 系统学习摄影 | 用现有设备随手拍，不懂曝光与系统选片；完成一组能解释取舍的日常生活照片 | 看见光，控制画面 → **构图与画面组织 / 自然光与困难光线** → 读作品 → 选片与基础后期 → 完成日常故事，带作品请教 |
| 系统学习大模型 | 会 Python 和 HTTP，数学生疏；以资料助手贯穿生成、检索、工具、训练与验证 | 第一次调用与生成直觉 → 必要数学小算例 → 资料接入 → **工具调用 / 训练与对齐** → 验证作品，提出值得问人的问题 |

并行载体共享已完成的前置、彼此不设必修依赖，后续阶段汇合它们的成果。载体内概念按推荐顺序编排。没有为了画出分支增加重复内容，也没有把不同教程二选一变成全部必学。

三个例子均保留真实访谈问题和明确的示例人物回答。AI 可帮助解释概念、整理证据和提出方案；用户希望获得审美、项目价值、个人取舍及真实经历方面的真人反馈时，可以带着具体作品和问题，寻找经验适合的实践者。路线描述这种使用方式，不编造作者身份、合作关系、咨询状态或背书。

首页六条流动建议仍按既有用户裁决保留原文和顺序：Agent 求职、快速理解 Transformer、强化学习后训练、二维傅立叶变换与二维卷积、个人理财、明代历史。它们是填写目标的快捷入口，与三条固定示例分别维护。

## 真实流程与内容校对

2026-09-13 在独立示例会话和隔离数据库中调用真实模型与知乎接口：三个目标均完成 R1、搜索、目录名称与补查、访谈、R4 和程序编译。首轮 R4 曾因本机沙箱 DNS 阻断未发到模型，保底结果未采用；恢复网络后保存实际正式输出。原始失败、成功输出、访谈和私有数据库保留在 Git 忽略目录。精简范围见[流程记录](../qa/evidence/showcase/workflows.json)。

路线经依赖和边界校对后，每条按顺序运行前三个概念的真实首次学习：检索规划、两路知乎检索、来源选择、连续讲解、引用关联与事务发布。没有额外生成追问或博主卡。真实模型与调用数、完成状态和检索并发记录在流程证据中；不使用固定回复或回放代替这些调用。

教学文本在原始生成基础上校对，来源摘要保持接口原文。主要校对包括：

- 理财区分必要程度与金额是否固定；同一笔消费只计一次；保留按月房租，统一核对收入中断、单次维修和可应急余额；不采用统一消费比例或收益承诺。
- 摄影区分光圈、快门改变曝光量与 ISO 影响信号处理；固定光圈手机使用实际可用控制；不把自动曝光变化当作光线变化，不把亮度补偿写成增加进光量。
- 大模型使用可运行请求与实际分词输出；不同 tokenizer 不混用于计费估计；先建立生成直觉，概率和 softmax 推导留在已安排的后续概念；核对思考模式与采样参数合同。

仅保留本节首轮讲解实际引用的来源，未引用的模型候选不添加为示例文章卡。来源身份、URL、摘要哈希、原始与发布文本哈希及候选选择见[来源账本](../qa/evidence/showcase/source-review.json)。审阅基于接口实际返回的摘要和教学内容，不声称逐篇完成知乎全文事实核查。

补充核对参考包括 [CFPB 应急储备指南](https://www.consumerfinance.gov/an-essential-guide-to-building-an-emergency-fund/)、[Investor.gov 风险说明](https://www.investor.gov/introduction-investing/investing-basics/what-risk)和 [DeepSeek 思考模式合同](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)。这些参考支持对应边界，不代表作者或机构参与本项目。

## 呈现与隔离

前端只保留简短“示例”身份。首页知识脉络从各路线第一个概念进入；概念目录只显示已准备的前三个学习状态。完整路线仍可浏览全部载体和概念；后续节点进入时说明示例范围，提供返回与开始自己的学习入口，不自动发起个人生成任务。

文章、正文、知识树与聊天共享同一份学习状态。每个 AI 块仍引用一张合法父卡；首轮只有一组用户消息与模型回复，没有额外作者关系。示例编辑进入独立版本化 sessionStorage，不覆盖个人资源、其他游客或原始文章来源。示例中的新提问引导开始自己的学习，不用固定回复冒充实时结果。

## 维护与验证

- `src/showcase/routes.json`：目标、访谈、载体、44 个概念及首轮讲解索引。
- `src/showcase/learnings.json`：仅 9 个已完成的学习状态。
- `src/showcase/sources.json`：仅对应首轮来源，摘要保持原文。
- `src/showcase/content.ts`、`catalog.ts`：版本、首页入口与现有组件投影。
- [流程记录](../qa/evidence/showcase/workflows.json)、[来源账本](../qa/evidence/showcase/source-review.json)：本轮日期、范围、调用、来源与哈希；旧搜索清单只代表过去验收。

`node scripts/build-showcase-sources.mjs` 仅重新打包当前已审阅来源，来源与账本不符时失败。修改数据后更新版本，运行 `node --test src/learning-v2/example-learning.test.mjs`、类型检查、全量测试、lint、构建及 `npm run check:docs`；还需在真实浏览器检查三条路线、九个概念入口、未预置节点、来源和窄屏。测试结果记录在带时间和范围的 QA 证据中。

固定示例的验收不能证明任意实时目标具有同等质量，也不代替生产身份、PostgreSQL 或并发容量测试。这些数据不得成为生产 provider 失败时的成功兜底。
