# 首页示例与内容维护

首页使用六条完整目标作为流动建议，预备知识脉络和学习路线统一为三组：Agent 开发工程师求职、明代历史、个人理财，共 23 个概念。示例复用当前路线、学习、来源阅读和知识树组件，与个人资源隔离。

## 三个目标与并行载体

| 目标 | 已知起点与成果 | 路线阶段 |
| --- | --- | --- |
| Agent 开发工程师求职 | 会 Python 脚本与 HTTP，首次做 LLM 应用；交付有检索、受控工具、评测与运行说明的文档助手 | LLM 应用基础 → **Agent 工具 / RAG 并行** → 评测与工程交付 |
| 系统了解明代历史 | 只有零散故事印象；建立时间脉络，连接制度与社会，比较历史解释的依据 | 明代通史 → **政治制度史 / 经济社会史并行** → 明史论题与历史解释 |
| 系统学习个人理财 | 无系统基础；用虚拟案例安排收支，核对费用、到账条件与可能损失 | 个人收支 → **应急资金 / 产品费用并行** → 流动性与风险判断 |

并行的两个载体都服务目标，基础内容彼此不设先修依赖；后续阶段需要汇合两边的成果。载体内概念按数组顺序排列，连接由程序编译，不能为了外观把真正的前置拆成并行。

六条流动建议按用户给定原文和顺序保存于 `src/showcase/content.ts`：Agent 求职、快速理解 Transformer、强化学习后训练、二维傅立叶变换与二维卷积、个人理财、明代历史。点击只填入输入框并聚焦，保留循环流动、悬停和键盘聚焦暂停。

## 真实流程与审阅范围

2026-09-09 三组示例分别运行实际 R1、知乎搜索、R2、访谈、R4 与路线编译发布。每组都完成两个首轮搜索；本次 R2 没有发现需要额外目录查询的载体，因此没有伪造第二轮目录搜索。访谈使用明确记录的示例人物条件，不是用户的个人资料。

随后逐一运行 23 个概念的真实首次学习：搜索项生成、分批知乎检索、来源选择、正文生成、卡片关联及事务发布。每组代表概念还实际完成一次问 AI 与一次问博主。调用经过共享门控，最多两路，开始间隔至少 2100ms；没有知乎直答、固定回复或回放响应冒充本次请求。中途发生流式失败与余额不足，失败记录保留，恢复后重跑成功的结果才可打包。

原稿在真实流程结束后人工审阅，修正范围、衔接、错误算例和过度结论。例如：统一 Agent 文档助手的练习材料；区分引用存在与结论得到支持；明史保留事件、解释和证据的区别；理财核对现金流算术、费用是否已计入净值、到账日定义及储备的重复计算。没有原样采纳作者的收益承诺或统一配置比例。

最终数据包含 139 块首次讲解，119 条按概念保存的来源记录（含跨概念重复），以及三个代表概念的真实追问。博主观点分别成卡，人工去除一条含明显保证性结论且不适配当前问题的候选后，共保留 8 张独立博主卡。来源摘要保持接口原文；来源选择与教学解释的修改不覆盖作者文章。

审阅对象为 API 返回的内容总结，不声称逐篇完成知乎全文事实审校。补充核对参考包括 [DeepSeek 消息接口](https://api-docs.deepseek.com/)、[JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)、[故宫博物院内阁说明](https://www.dpm.org.cn/court/system/236394.html)、[CFPB 应急资金指南](https://www.consumerfinance.gov/an-essential-guide-to-building-an-emergency-fund/)及 [Investor.gov 投资产品说明](https://www.investor.gov/introduction-investing/investing-basics/investment-products)。

## 前端呈现

前端仅保留简短“示例”身份，不呈现人工润色、编辑过程、原稿存档或面向投资人的制作说明。内部运行和编辑记录保存在 Git 忽略目录；精简验收记录位于 QA，不导入产品界面。

首页每个知识脉络入口选择具有代表性的概念：Agent 的证据与引用、明史的白银与财政、理财的流动性与风险。其余概念均能从现有目录打开，含目标、四项概念总结、连续 H2 讲解和真实来源。文章、正文、知识树与聊天共享同一份学习状态。示例编辑进入独立版本化 sessionStorage，不覆盖个人资源或原始文章来源；新对话保留文章和知识树。示例中的新提问引导开始自己的学习，不用固定回复冒充实时模型结果。

- `src/showcase/routes.json`：三个目标、访谈条件、阶段数组、概念总结与讲解索引。
- `src/showcase/learnings.json`：23 个已完成且审阅的学习状态。
- `src/showcase/sources.json`：保留原摘要的来源目录。
- `src/showcase/content.ts`、`catalog.ts`：首页文案、版本和当前组件投影。
- [真实流程记录](../qa/evidence/showcase/workflows.json)、[本轮搜索清单](../qa/evidence/showcase/search-inventory-2026-09-09.json)、[来源审阅账本](../qa/evidence/showcase/source-review.json)：日期、范围、来源 ID 与哈希。

`node scripts/build-showcase-sources.mjs` 仅从当前学习状态重新打包已审阅来源；来源与账本不符会失败，不重新搜索或自动排名。修改数据后更新版本，运行 `node --test src/learning-v2/example-learning.test.mjs`、类型检查、全量测试、lint、构建和 `npm run check:docs`，并检查实际浏览器中的路线、概念入口与窄屏。测试命令与日期范围见 [QA 入口](../qa/README.md)。

这些固定示例的质量不能证明实时生成链路在任意目标上都达到同等水平。来源不表示作者参与制作或背书，示例不产生真实作者关系、咨询状态或个人学习任务。它们不得成为生产 provider 失败时的成功兜底。
