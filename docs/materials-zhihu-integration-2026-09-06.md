# 资料与知乎账号接入 · 2026-09-06

本轮按用户提供的知乎搜索、PDF 异步解析、OAuth、公开创作和收藏 API 文档实现。最新裁决覆盖过去“学习不读附件”的限制。

## 产品关系

首页选择文件或收藏夹 → 固定资料快照 → 全部路线步骤理解目标和已有资料 → 发布路线 → 各概念继承全部资料目录 → 默认阅读全部目录并按概念选取依据 → 用户引用资料继续长单父卡 → 真实知乎作者形成主题使用足迹。上传文件没有作者身份时不进入博主网络。收藏只表示兴趣，不等于帮助反馈或使用积分；导入来源进入 network-first 检索，后续真实采用才增加对应主题偏好。

## 当前外部条件

本轮检查到 Access Secret 已配置，OAuth app_id/app_key/redirect_uri 尚未配置。用户提供文档说明需申请应用，也提到用户信息接口，但没有其 URL、鉴权参数、稳定 ID 字段；实现不得猜测这些字段。用户已答复“尚未申请，先完成可配置的接入”。可配置实现已落地，真实知乎账号登录与授权收藏夹验收必须待凭证及官方用户信息合同齐全后进行。不能把开发者 Access Secret 本人内容当作终端用户收藏。

PDF API 最大 100MB，summary 可为空；解析任务幂等创建，成功后立即读取临时结果链接并保存解析正文，用户阅读摘要。配置/鉴权不通、业务 failed 或解析正文与摘要同时为空不会发布成功资料。

## OAuth 配置与验收边界

1. 申请并填写 `ZHIHU_OAUTH_APP_ID`、`ZHIHU_OAUTH_APP_KEY`；`ZHIHU_OAUTH_REDIRECT_URI` 为公开站点的 `/api/auth/zhihu/callback`，生产使用 HTTPS，且与 `THREADPEAK_PUBLIC_ORIGIN` 同源。
2. 向知乎取得用户信息接口合同后配置 `ZHIHU_OAUTH_USERINFO_URL` 与稳定 ID 字段路径 `ZHIHU_OAUTH_USER_ID_PATH`。名称/头像可用 `ZHIHU_OAUTH_USER_NAME_PATH`、`ZHIHU_OAUTH_USER_AVATAR_PATH`。当前适配器以 Bearer Token 读取指定官方端点；正式合同若不同，必须调整适配器并再验收，不能凭猜测填端点。
3. `THREADPEAK_TOKEN_SECRET` 至少 32 个随机字符，只保存在服务端，用于 AES-GCM 加密用户令牌；也可明确复用已有身份密钥。不要把这些值发到聊天、前端或仓库。
4. 授权开始时持久保存一次性随机 state 与浏览器 Cookie 绑定；回调严格校验并消费后交换令牌。需确认知乎应用回传 state；未回传时不能关闭校验绕过。账号按平台稳定 ID 与 app_id 绑定，Token 更新不产生新账号。
5. 账号 Cookie 为 HttpOnly/SameSite，生产 Secure；用户 Token 不返回浏览器。授权到期后要求重新连接，不猜刷新/撤销接口；退出清除本次本地会话。已有本地工作区与知乎账号分开，不自动把匿名资料并入另一个账号。
6. 配置完整只代表显示可连接入口。真实知乎登录、授权范围、跨账号收藏隔离、过期重连必须待应用获批后验收；本轮替身测试不替代真实 OAuth。

## 容量与保留

每次最多 8 份资料（一个收藏夹算一份）；PDF 最大 100 MiB，文本文件最大 10 MiB，解析正文上限 200 万字符。收藏夹/创作逐页读取，当前工程上限 2,000 条及 200 万字符，超过范围不发布不完整快照；最近收藏只代表接口当次返回范围。大型收藏、超过模型窗口的结构分区与并发大文件上传仍需负载/质量验收，不承诺任意规模都能完成。

PDF 成功后清除原二进制暂存，保留解析正文与总结；未完成暂存用于恢复。正式资料保留、账号删除、备份清理期限仍需产品运营确定。
